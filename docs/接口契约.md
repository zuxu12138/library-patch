# 接口契约 · 三人 Day 1 定死,之后不许单方改

> 三条契约是三人并行的地基。**改契约需三人同意,改完同步更新调用方。** 单方改 = 把队友代码改崩。
>
> 全局已定的三个决策：
> - **响应格式**：统一信封 `{code, msg, data}`（所有 Java REST 和 Agent 接口）
> - **用户身份**：HTTP 头 `X-User-Id` 传递（不污染业务参数）
> - **链路追踪**：HTTP 头 `X-Trace-Id` 传递（agent 生成,贯穿两层日志）

---

## 全局约定（三条契约共用）

### 统一响应信封

所有接口（Java REST + Agent）成功/失败都用同一层信封：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

| 字段 | 含义 |
|---|---|
| `code` | 0=成功；非 0=业务错误码（见下表） |
| `msg` | 人类可读说明；成功为 "ok" |
| `data` | 业务数据；失败时为 `null` |

**错误码段位**（避免三人撞码）：

| 段位 | 归属 | 示例 |
|---|---|---|
| `0` | 成功 | — |
| `40001-40099` | 请求错误(参数缺失/非法) | 40001 缺少 query |
| `50001-50099` | Java 数据层(A) | 50001 OPAC 超时；50002 座位系统不可达 |
| `60001-60099` | Agent 层(B/C) | 60001 LLM 不可用；60002 记忆库异常 |

### 统一请求头（每个请求都带）

| 头 | 必填 | 含义 | 谁生成 |
|---|---|---|---|
| `X-User-Id` | 是 | 用户标识,记忆按此隔离；无登录时前端填 `default` | 前端/调用方 |
| `X-Trace-Id` | 是 | 链路 id（8 位 hex）,贯穿两层日志 | agent 生成 |
| `X-Internal-Token` | 公网部署时 | agent↔Java 内部鉴权 | 环境变量 |

## 契约 ② Agent 循环签名 + MemoryEntry（B ↔ C）

B 实现 `AgentLoop` 与 `MemoryEntry`,C 调用。签名定死,B 内部实现随便改。

### AgentLoop.run（C 调它跑一次任务）

```python
async def run(
    self,
    feature: str,          # 功能名: "findbook" / "knowledge_map" / "seat_predict"
    subject: str,          # 记忆主题, 如 "找书"
    task: str,             # 人类可读任务描述
    tool_name: str,        # 要调的工具名
    tool_args: dict,       # 工具参数
    user_id: str,          # 用户隔离, 来自 X-User-Id
    trace_id: str,         # 链路 id, 来自 X-Trace-Id
    query_key: str | None = None,  # tool_args 中"检索词"的键, 给出则走记忆精炼
) -> AgentResult
```

**AgentResult 字段**（C 拿到后组装成信封 data）：

```python
feature: str            # 功能名
output: Any             # 工具产出(如书目列表)
memories_used: list[str]  # 命中的记忆 id
elapsed_ms: float       # 耗时
tokens: int             # 本次 token 消耗
plan_note: str          # 规划器给用户的说明(如"已按你的偏好只找近五年")
used_llm: bool          # 本次是否真调了 LLM
trace_id: str           # 回传, 便于日志串联
```

### AgentLoop.record_feedback（C 把反馈入环）

```python
async def record_feedback(
    self,
    feedback: str,          # 用户反馈原文
    user_id: str,           # 用户隔离
    task_context: str = "", # 任务上下文(如 "找书:机器学习")
    trace_id: str = "",
) -> list[str]              # 返回新沉淀的记忆 id; 幂等(重复反馈返回已存在的 id)
```

### MemoryEntry 字段（B 定义,C 只读不建）

```python
user_id: str            # ★ 多用户隔离
type: str               # preference / rule / episode
subject: str            # 主题, 如 "找书"
content: str            # 记忆正文
applies_to: str = "*"   # 适用功能范围
confidence: float = 0.8 # 置信度
source: str = ""        # 溯源: 由哪条反馈抽取
dedup_hash: str         # ★ 幂等去重(user_id + 内容 hash)
entry_id: str           # 唯一 id
created_at: float       # 供时间衰减
updated_at: float
```

## 契约 ③ trace_id 传递（三人）

一个 id 串起两层日志,排查"找书失败"不用肉眼对时间戳。

**流转链路**：

```
前端/调用方
  └─ agent (B 在 agent_loop 生成 8位hex trace_id)
       ├─ 打进 agent 自己的日志:  [a1b2c3d4] findbook query=机器学习
       └─ C 在 service_client 注入请求头 X-Trace-Id: a1b2c3d4
            └─ Java (A 在过滤器读入, 放进 MDC)
                 └─ 打进 Java 日志:  [a1b2c3d4] OPAC search ok total=6101
```

**三人各自的活**：

| 谁 | 在哪 | 做什么 |
|---|---|---|
| B | `core/agent_loop.py` | 每次 run/record_feedback 开头生成 trace_id（无则新建,有则透传） |
| C | `service_client.py` | 调 Java 时注入 `X-Trace-Id` 头；日志打 trace_id |
| A | Java 过滤器 | 读入 `X-Trace-Id`,放进 MDC,所有日志自动带上 |

**格式**：8 位十六进制（如 `a1b2c3d4`）。够短好认,冲突概率对赛期够用。
