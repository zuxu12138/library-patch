# 三人分工 · 文件级归属规则

> 核心原则：**按层横切,不按功能竖切**。三个功能共享同一套记忆内核,谁都别单独占一个功能,否则天天撞记忆库的代码。
>
> 铁律：**只改自己名下的文件;要动共享文件,先在群里喊一声再改;契约三人同意才改。**

---

## 角色速记

- **A · 数据侧**(Java + 采集器)：把脏接口喂成干净数据。技能：Java/Spring + 运维。
- **B · 大脑侧**(Python 内核)：反馈记忆闭环,04 赛道护城河,最深的一块。技能：Python + LLM。
- **C · 粘合侧**(功能 + 前端)：把 A 的数据和 B 的内核拼成用户能用的产品。技能：Python + 前端。

一句话：**A 管数据进来,B 管记忆变聪明,C 管用户用得上。**

## 共享文件(谁都别单独改,改前群里喊)

| 文件 | 谁维护 | 规则 |
|---|---|---|
| `agent/config.py` | C 主维护 | 加环境变量前群里说一声,避免同时改 |
| `agent/requirements.txt` | 谁加依赖谁加行 | 只**追加**自己那行,不删别人的 |
| `agent/.env.example` | C 主维护 | 同 config |
| `.gitignore` / `README` / `docs/` | 谁都可加 | 只追加,不删改别人段落 |

## 三条接口契约(Day 1 三人当面定死,写进 docs,之后不许单方改)

| 契约 | 涉及 | 内容 |
|---|---|---|
| ① Java REST 字段 | A↔C | `/api/books/search`、`/api/seats/now` 的请求参数 + 返回 JSON 结构 |
| ② Agent 循环签名 | B↔C | `AgentLoop.run(...)` / `record_feedback(...)` 参数;`MemoryEntry` 字段 |
| ③ trace_id 传递 | 三人 | agent 生成 → `X-Trace-Id` 头 → Java 读入 |

**改契约的唯一规则：三人同意才能改,改完同步更新调用方。** 单方改契约 = 把队友代码改崩。

---

## 跨层协作边界(谁在谁的地盘写自己那半)

| 横切事项 | 各自负责的半边 |
|---|---|
| 鉴权 token | A 写 `AuthFilter.java` 校验;C 在 `service_client.py` 加请求头 |
| trace_id | B 在 `agent_loop.py` 生成;C 在 `service_client.py` 注入头;A 在 Java 过滤器读入 |
| 缓存 | A 在 Java 侧(Caffeine);C 在 `knowledge_map` 加 S2 缓存文件 |
| WAL 并发 | A 在采集器建库设 WAL;C 在 `seat_predict` 读连接设 busy_timeout |
